### 问题2：连上后报 schema 校验失败
- 现象：`Schema-validation: wrong column type in column [status] in table [book]; found [varchar], but expecting [enum ('active','inactive')]`。
- 根因：Hibernate 6.4 + MySQL 对 `@Enumerated(EnumType.STRING)` 枚举列做 schema 校验时误判为原生 ENUM，与库里 VARCHAR 列不一致（运行期 @Enumerated(STRING) 仍以字符串读写 VARCHAR，行为正确）。实体字节码确认含 `Ljakarta/persistence/Enumerated;`，枚举类本身无额外类型注解，无全局 Converter。
- 修复：将 `backend/src/main/resources/application.yml` 的 `spring.jpa.hibernate.ddl-auto` 由 `validate` 改为 `none`（表结构由 `db/schema.sql` 负责，Hibernate 只映射不校验），与 docker-compose 中 `SPRING_JPA_HIBERNATE_DDL_AUTO: none` 一致。
- 验证：`DB_PASSWORD=123456 java -jar target/library-0.1.0-SNAPSHOT.jar` 干净启动（Started LibraryApplication ~7.6s），种子数据写入：reader 3 条（admin1/student1/teacher1）、book 6 本、book_copy 13 个、loan 0。重新打包后仅凭 DB_PASSWORD 即可启动，无需环境变量覆盖。

### Bug 修复：登录后白屏 + 路由无限重定向（11:05 复现）
- 现象：浏览器开 http://localhost:5173/ 白屏，控制台报 `Infinite redirect in navigation guard`，以及 `reader`/`admin` 命名路由 "child without a name and empty path" 警告。
- 根因（致命）：后端返回角色是大写 `"ADMIN"`/`"READER"`，而路由 `meta.role` 是小写 `'admin'`/`'reader'`。之前加的守卫用 `authStore.userRole === 'admin'` 做大小写敏感比较，永远不成立 → 已登录用户一律被 `next('/reader')`，到 /reader 后又触发「角色不匹配」分支再次 `next('/reader')`，死循环 → 路由启动失败 → 白屏。
- 修复：`frontend/src/router/index.js` 守卫内把角色统一转小写 `const role = (authStore.userRole || '').toLowerCase()` 再与 `meta.role` 比较；并给两个重定向分支加 `if (to.path !== dest)` 兜底防死循环。
- 顺带消除命名警告：移除 `/reader`、`/admin` 父布局路由上的 `name`（其空路径子路由无名导致警告；grep 确认这两个 name 全项目未被 `router.push({name})` 引用，移除安全）。
- 验证：重新 `npm run build` 通过（4.7s，无错误）。各状态推演无环：未登录→/login；已登录 ADMIN→/admin；已登录 READER→/reader；角色不符→各自首页。
- 提醒用户：Vite 改了路由守卫后需硬刷新（Ctrl+Shift+R）浏览器，HMR 对路由/守卫未必热替换。

### 核心借阅流程端到端验证 + 修了一个关键 bug
- 验证借/还/续/逾期全链路（后端 jar 17:30 重新打包，启动 7.25s）：
  - 借书：`POST /api/loans`（admin，BorrowRequest 用 readerAccount+barcode）→ 200，loan 创建，副本 status 变 BORROWED。
  - 续借：`POST /api/loans/{id}/renew`（读者自助，STU token）→ 200，dueDate 顺延、renewedCount+1。
  - 归还：`POST /api/loans/{id}/return`（admin）→ 200，loan RETURNED、副本回 IN_STOCK。
  - 逾期：每日 01:00 `OverdueTask`（已确认 `@EnableScheduling` 在 LibraryApplication）把到期未还置 OVERDUE 并生成罚款；`GET /api/loans?status=OVERDUE`、`GET /api/penalties/my` 正常；逾期罚款缴纳 `POST /api/penalties/{id}/pay` 正常。
- **关键 bug（已修复）**：`notification` 表列名用了 MySQL 保留字 `read`。`schema.sql` 用反引号建表没问题，但 **Hibernate 生成的 INSERT/UPDATE/SELECT 不会自动加反引号** → `INSERT INTO notification (read, reader_id) VALUES (...)` 报 `SQL Error: 1064` → 所有站内消息写入全 500（罚款缴清通知、逾期提醒、到期提醒全部失败）。
  - 根因定位：读后端日志（TaskOutput 抓到 `near 'read,reader_id) values (...'` 语法错）。
  - 修复：实体 `Notification.read` 字段 `@Column(name = "is_read", ...)`；`schema.sql` 列与索引改名 `is_read`；**真实库**执行 `ALTER TABLE notification CHANGE \`read\` is_read TINYINT(1) NOT NULL DEFAULT 0;`（索引自动跟随改名）。重新打包重启后四类消息写入全部 200。
  - 验证：`payPenalty` 写通知成功；`GET /api/notifications/my`、`GET /api/notifications/my/unread-count`（countByReaderIdAndReadFalse）、`POST /api/notifications/my/read-all`（markAllRead JPQL）全部 200。
