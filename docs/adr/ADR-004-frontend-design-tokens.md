# ADR-004: 前端设计令牌层（--sl-* + Element Plus 变量桥接）

- 状态：已采纳（2026-09-25，restyle-visual-system 建立，restyle-warm-library 验证）

## 背景

三端最初是 Element Plus 默认蓝的"裸皮肤"，`#409eff` 硬编码散落约 20 个文件。第一次主题化（书卷青）时 35 个文件逐一改色；随后用户要求**再次整体换风格**——若每次换肤都要全仓扫色值，成本不可持续。

## 决策

在 `style.css` 顶部建立双层令牌：

1. 自有语义令牌 `--sl-*`（primary/accent/bg/text/muted/border/ring/阴影/圆角/字体栈）——业务代码唯一允许引用的色值
2. Element Plus 桥接——把 `--el-color-primary` 六档阶梯、danger/warning、文字/边框/填充变量指到 `--sl-*` 或其推导值，组件库整体跟随

禁止业务代码出现裸色值（code review + grep 双检查）。

## 后果

- ✅ **第二次换肤（书卷青→暖木书斋）实测**：约 30 个视图文件零改动，手改收敛到 `style.css` 令牌区 + 3 个文件的主题专属硬编码——投资完全兑现
- ✅ 可读性分档（主色对白底不足 4.5:1 时的压深色）集中在一处，对比度补丁可程序化验证
- ⚠️ EP 阶梯需按混色规则手工推导（已脚本化）；极端定制场景（如组件级特殊色阶）仍需个别覆盖
- ❌ 被否备选：Tailwind（违反项目技术栈规定且与 EP 变量体系重叠）；逐文件硬编码（即当初的债）
