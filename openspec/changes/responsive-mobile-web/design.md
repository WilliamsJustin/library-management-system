# Design: 全站响应式（电脑端 + 手机端网页版）

## Context

系统前端为 Vue 3 + Element Plus 的单体 SPA（Vite 构建，无 SSR），三处壳层：公共前台 `PublicLayout`（横向导航 + 页脚）、读者后台 `ReaderLayout` 与管理后台 `AdminLayout`（两者骨架几乎相同：`el-header` + 200px `el-aside` 菜单 + `el-main`，`100vh` 高度锁定、内容区内部滚动）。约 10 个页面使用 `el-table` 承载数据，卡片与弹窗宽度多为写死 px。动机与范围见 proposal.md；本设计只回答"怎么改"。

## Goals / Non-Goals

**Goals:**
- 以 768px 为唯一断点实现手机版形态，且电脑端（>768px）样式与模板零改动、逐像素回归一致
- 结构级切换（表格↔卡片、侧栏↔抽屉）与样式级切换（字号/间距/宽度）分离实现，各自可独立验证
- 菜单单一数据源，桌面侧栏与手机抽屉不漂移
- 每期改造可独立 type-check 与人工走查，不阻塞其他期

**Non-Goals:**
- 不改任何后端接口、数据库与业务逻辑
- 不做平板档（769–1024px 按电脑版）
- 不做 PWA/离线/原生壳，不做触控手势（下拉刷新等）
- 不重构既有桌面样式（如把 px 全面改成 rem/fr），手机版只在媒体查询内覆盖

## Decisions

### D1 双层切换：媒体查询管样式，`matchMedia` 管结构
样式差异（字号、内边距、宽度收缩、堆叠方向）全部走 `@media (max-width: 768px)`；结构差异（表格→卡片、侧栏→抽屉）用新增的 `composables/useBreakpoint.ts` 提供响应式 `isMobile`，在模板中做 `v-if="!isMobile"` / `v-else` 双分支。`isMobile` 在 setup 阶段同步初始化（`window.matchMedia(...).matches`），并监听 `change` 事件更新，CSR 下无首屏闪烁，也避免了 SSR  hydration 问题（本项目不涉及）。

- 备选 A：纯 CSS 把 `el-table` 的行/单元格改 `display:block` 伪装卡片。放弃：Element Plus 表格 DOM 层级深（含固定列/多级表头时更甚），CSS 伪装脆弱且排序、列宽、`::before` 取列名都需要额外 hack。
- 备选 B：`::before` content 方案需要给每列手工绑定 `label` 到 DOM，el-table 不暴露此钩子。同上放弃。
- 备选 C：独立手机路由树（`/m/...`）。放弃：路由/守卫/状态两份维护，与"一个网站两种形态"的诉求相悖，且分享链接、登录回跳全都要改。

### D2 桌面优先、只增不改（桌面不变形的硬保证）
所有手机规则只写在 `max-width:768px` 块内；桌面模板、桌面 CSS、既有 JS 逻辑一行不动；手机卡片模板一律是新增 `v-else` 分支。收敛两个旧断点：`SearchResultsView` 的 900px 与 `BookDetailView` 的 720px 规则合并进 768 约定（770–900px 区间由"侧栏堆叠"变为"电脑版"，属已声明接受的可见变化，见 spec「旧断点收敛」场景）。

### D3 菜单抽共享组件 `LayoutSideMenu.vue`
读者/管理后台的菜单是同一形态（图标 + 文案 + index + 激活态 + 路由跳转），把菜单项定义与渲染抽成共享组件：桌面渲染在 `el-aside`，手机渲染进 `el-drawer`（两个后台各持一份菜单数据数组传入）。避免"侧栏一套、抽屉一套"的漂移风险。抽屉用 `el-drawer`（direction ltr、`append-to-body`），关闭后焦点归还汉堡按钮。

### D4 三处导航壳的手机形态（按已确认的产品决策）
- **公共头部**：`≤768px` 隐藏 `.nav` 与登录/注册横排，显示汉堡；抽屉内含全部一级导航（含「本馆概况」的三个子项直接平铺）与登录/注册/进入后台/用户菜单。页脚 `.footer-info` 由横排改纵排、去竖线分隔。
- **ReaderLayout**：aside 改抽屉；新增固定底部 Tab：`首页 / 图书借阅 / 借阅查询 / 我的罚款 / 我的（更多）`，「我的」展开其余菜单（我的收藏、帮助与反馈，及教师可见的发布公告、活动管理）。`el-main` 底部预留 Tab 高度内边距防遮挡。
- **AdminLayout**：仅抽屉，不加底部 Tab；头部实时咨询角标、「进入前台」、用户下拉保持可见可点（角标与轮询逻辑不动）。

### D5 表格卡片化：摘要 + 展开详情
手机模板为每行渲染一张 `.m-card`：头部=核心标识（如图书名称/ISBN、读者账号/学号），主体=核心字段行（状态 + 关键时间/数值），底部=操作按钮区（复用桌面同一组操作，按钮事件与表格行内完全一致，不新增第二套逻辑）。列数 >8 的表单加「展开详情」开关，展开渲染其余字段为定义列表。筛选区在手机端 `flex-direction: column`、全宽。卡片整体可点击（与桌面行点击一致）时，操作按钮区 `stopPropagation` 防误触。

### D6 弹窗与全局小屏规则放 style.css（全局块）
`el-dialog`  teleport 到 body，scoped 样式管不到，因此在全局 `style.css` 增加 `@media (max-width: 768px)` 块：`.el-dialog { width: 92vw !important; max-width: 92vw; }`（覆盖 el-dialog 的行内 width；个别需要例外的弹窗加专用 class 提高特指度回退）；`.el-pagination__jump`、`.el-pagination__sizes` 隐藏（保留总数 + 上/下页 + 页码）；`el-form` 抽屉/弹窗表单的重排按 D7。另设安全网：未被卡片化覆盖的表格容器允许 `overflow-x: auto`。

- 备选：逐个弹窗把 `width` 改成 `:width="isMobile ? '92%' : 560px"`。放弃：20+ 处弹窗逐一改动易漏，全局规则一处生效。

### D7 表单弹窗标签上浮
编辑类弹窗（图书、读者、公告、活动、FAQ）的 `el-form` 增加 `:label-position="isMobile ? 'top' : 'right'"` 绑定（每个表单只改一个属性），配合 D6 的宽度规则，手机上输入框占满一行。

### D8 触控与安全区
手机端按钮/导航项最小点击区 40×40px（全局 CSS 对 `.el-button--small`、`.el-pager li`、`.footer-nav-item` 等在媒体查询内补 `min-height`；`.service-card` 等改 `width:100%`）。底部 Tab 加 `padding-bottom: env(safe-area-inset-bottom)`。

### D9 验证策略
- 类型门禁：`pnpm run type-check` 零报错（每期结束跑一次）。
- 视觉走查：浏览器设备模拟在 375px / 390px / 768px / 1440px 四档逐路由截图；1440px 档与改造前同路由截图比对，允许零差异（桌面回归的唯一标准）。
- 交互走查：抽屉开合与焦点归还、Tab 切换与高亮、卡片展开详情后翻页/筛选保持、跨断点缩放不丢查询条件（对应 spec 场景逐条过）。

## Risks / Trade-offs

- [桌面端回归] 手机规则渗漏到桌面 → 只增不改（D2）+ 1440px 四路由以上截图比对作为唯一验收标准；发现差异即回退该文件改动。
- [双模板维护成本] 表格页同时维护表格与卡片两份模板 → 卡片只做展示，数据/筛选/分页/操作方法全部复用桌面同一份代码，禁止在卡片里重写业务逻辑；后续新增列时在 tasks 约定中提醒同步两处。
- [菜单漂移] 侧栏与抽屉两份菜单 → 共享 `LayoutSideMenu`（D3），菜单项数组单一数据源。
- [matchMedia 边界] 浏览器不支持/事件不触发 → 目标是现代浏览器（Vite 目标 + Element Plus 2.x 要求），不支持时 `isMobile` 恒为 false，退化为电脑版，可接受。
- [全局 `.el-dialog !important` 误伤] → 仅存在于 768px 媒体查询内；需要固定宽度的手机弹窗用专用 class 提权回退；验收走查全部弹窗确认。
- [卡片展开态与分页交互] 展开后翻页是否保持 → 展开态只存在组件内 `ref<Set>`，不与查询条件耦合；spec 场景「展开不影响筛选与分页」验收。
- [768–900px 区间] 检索/详情两页行为变化 → 已在 spec 声明为收敛旧断点的可接受变化；如用户不接受可给这两页单独保留 900px 规则（工作量 +2 处）。
- [变更集中] 35 文件一次性改动评审困难 → 按 6 期推进（见 tasks.md），每期独立可验证、可暂停。

## Migration Plan

纯前端变更，无数据库、无接口、无依赖新增：构建产物为静态文件，回滚 = 重新部署改造前的 `dist`（或按变更文件清单反向恢复改动文件）。上线顺序无服务端依赖，可随时发布。上线后观察项：手机端四档宽度逐路由走查记录、桌面 1440px 回归截图归档。
